## Critical

**C1 — `goal-orchestrator.ts:111` · evaluator failure fails the turn before *any* rail advances, and recovery re-queues it forever with uncapped metered spend.**

Chain:
1. `runClaimedIteration` order is: `checkRails` → `capabilities.roster()` → `evaluator.evaluate()` → … → `dispatch()` (which calls `reserveIteration`) → `recordProgress`.
2. `RoutedGoalEvaluator.evaluate` throws on: Anthropic 429/5xx after `maxRetries: 1`, `stop_reason === "refusal"` (`goal-evaluator.ts:177`), `JSON.parse` failure (`:180`), `validateDecision` (`:219–231`), and **`selected ineligible agent` (`:138`)** — the last is model-deterministic and therefore *persistent*, not transient.
3. The throw escapes `runClaimedIteration`. `runIteration` releases the lease in `finally` but `queueNext` stays `false`. Queue is `attempts: 1` (`session.queue.ts:73`) → job dies.
4. `reserveIteration` was never reached → `goal.iterations` does **not** increment → `MAX_ITERATIONS = 100` never trips. `recordProgress` was never reached → `stuckCount` does **not** increment → `stuckThreshold` never trips.
5. `GoalContinuity.recoverStalledGoals` sees `status=active`, no lease, no live session → re-queues, forever, every ≥15 min.
6. Each pass makes one `claude-opus-5`, `effort: high`, ~30 KB-prompt cloud call. **`goal_decisions` has no cost column** (`packages/db/src/schema/company.ts:68–86`) and nothing calls `recordSpend` for it, so `goal.spendUsd` never moves → the spend rail never trips either.

Only `stopped-time` can end this, and `maxDurationMinutes` defaults to `null` with no confirmation gate (`contracts/goal.ts:35`), while a *missing spend cap* is gated (`:40`). So the documented-safe configuration — spend cap set, no time cap — is exactly the one that loops forever spending money the cap cannot see.

This is the same defect H1 described, moved one call earlier. **Blocks unattended use.**

Minimum to close: charge evaluator usage to `goal.spendUsd`, and make a failed iteration advance `stuckCount` (or a separate failure counter) before it propagates.

## High

**H1(new) — `goal-orchestrator.ts:216–287` · any throw inside `dispatch()` still kills the whole turn's bookkeeping, and `Promise.all` makes a fan-out fail on its weakest child.**

The handoff write is now wrapped, but `dispatch` still throws on `agents.requireByName` (agent deleted mid-goal → `NotFoundException`), `router.resolve` → `LocalRunnerUnavailableError` (worker rebooted / drained under a `local`-pinned goal), and every `goalLog`/`goals` DB call. `Promise.all` at `:170` rejects on the first of N children, so `recordProgress` at `:191` is skipped for siblings that *did* finish — and those siblings keep running detached, writing spend and handoffs into a turn nobody will account for.

Here `reserveIteration` *has* run, so `iterations` grows and the goal converges on `MAX_ITERATIONS` — but at ≥15 min per recovery pass that is ~25 hours of a `local`-pinned goal silently doing nothing while the worker is down. **Degrades unattended use; does not block it.**

Use `Promise.allSettled` and move `recordProgress` into a `finally`.

## Medium

**M1 — `preflight.service.ts:94–106` · the `agent-advisory` finding is unreachable for project and goal preflight.**

`requiredRoles` is populated only inside the `subjectType === "template"` branch (`:75`). For `project` and `goal` the loop body never executes, so `card.advisories` is never turned into a finding. `grep advisories apps/web/src` → no hits, so no screen renders the array either. Net: on the goal screen and the company-setup screen a missing recommended skill is invisible. The claim "Preflight reports it as an `agent-advisory` info finding" is true only for workflow preflight. **Does not block; the M2 fix is narrower than described.**

**M2 — `preflight.service.ts:237–247` · writing only on failure puts the write on the polled path, so the briefing duplicates.**

`company-setup.tsx:31` reads preflight through `useQuery` (GET). TanStack Query refetches on window focus and on `invalidateQueries` after every blueprint/slot mutation. On a *blocked* project each of those now inserts a row, and `briefing.service.ts:25` maps every row in the last 24 h to its own `failures` item. Ten focus events → ten identical "project failed preflight" entries in the executive briefing, and unbounded row growth on precisely the project that is broken. The old behaviour wrote more rows but the briefing read the same subset. **Does not block; degrades the one screen meant to be read unattended.** Dedupe on `(subjectType, subjectId, findings-hash)` or write at most one row per subject per interval.

## Low

**L1 — `handoffs.service.ts:95` · `slice()` can split a surrogate pair.**

`trimmed.slice(0, 3_999)` on a summary ending in an emoji at the boundary yields a lone surrogate; `jsonb` rejects the resulting escape ("Unicode low surrogate must follow a high surrogate") and the insert throws. Now caught and logged rather than fatal, so the consequence is a silently lost handoff, not a dead turn. Same class: a `\u0000` anywhere in agent output.

**L2 — `DEPLOY.md` §6 · "When all slots are busy, requests queue at the worker rather than spilling to cloud" is false for `auto`.**

`runner-router.ts:134` and `goal-evaluator.ts:108` both branch on `status.ready`, which `capacity.ts:27` sets false at capacity. Under `auto`, a busy local worker sends the session *and* the goal decision to the metered cloud. Only explicit `local` queues. The sentence two paragraphs above states this correctly for explicit `local`; the general one contradicts it.

**L3 — `catalog.service.ts` `grantRecommendedSkills` doc vs code.** The comment says "it only ever writes onto an empty list", but the update is a union onto whatever `skillIds` holds whenever `recommendedSkillsInitialized` is false. Behaviour is safe — operator edits set `initialized = true` (`agents.service.ts:207`) — but the comment describes a guard that is not there.

**L4 — `handoffs` has no unique index on `session_id`** (`schema/company.ts:106–110`). `ensureForSession`'s find-then-insert is racy; two concurrent closers write two rows. Harmless today (`latestFor` is bounded), noted because the method's contract reads as idempotent.
